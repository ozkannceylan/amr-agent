# plc

## This layer must not access

- Fleet management concerns: order assignment, traffic control, zone reservation. Those belong to the fleet manager (invariant 5).
- The MQTT broker or any VDA 5050 topic. The PLC talks to the fleet layer only as an OPC UA server; it never acts as an OPC UA or MQTT client (invariants 4, 11). The same holds towards the bridge: the PLC serves nodes and never calls out to it (ADR 0005).
- ROS 2, Nav2, Gazebo or any vehicle-internal interface. The PLC never sees a topic; every simulated signal reaches it as an OPC UA node written by the bridge (invariant 11, ADR 0004).
- The network as a safety path. Safety functions live in the F-CPU program over PROFIsafe and onboard the vehicles; no e-stop, protective stop or STO signal may depend on MQTT, OPC UA or VPN (invariants 1, 2).
- Standard-program dependencies inside the safety program. The F-CPU logic must remain correct if the standard program halts or misbehaves (invariant 7).
- Tailscale or any engineering-access tunnel as an I/O or data path (invariant 8).

Owns: fixed equipment (conveyor, door, charger), interlocks, station handshakes, and the F-CPU safety program.

## The demonstration cell's red mushroom is a PROCESS stop

`PanelProcessStopCircuitClosed` in `demo-cell/SPEC.md` is a process stop input to
the **standard** program. It is not an emergency stop, carries no SIL or PL claim
and implements no safety function of `docs/safety/SRS.md` (ADR 0004). No node
served over OPC UA is a safety path (invariant 1), and the demonstration cell has
no F-CPU at all.
