# M5 closure implementation plan

> **For agentic workers:** this project's execution unit is a **brief** under
> `docs/briefs/`, dispatched to a roster agent, answered by a **report** under
> `docs/reports/` — CLAUDE.md §5, which overrides the step-level TDD format the
> writing-plans skill defaults to. Each task below is one brief. Steps use
> checkbox syntax for tracking.

**Goal:** Close roadmap criterion (d) and (e) for one vehicle, finished to
standard, so M5 can be verified and recorded.

**Architecture:** HMI → PLC standard program (mode arbiter, envelope) → OPC UA →
bridge → vehicle image in its own DDS domain → Nav2 → Gazebo, with the F-program
as the vehicle's onboard safety controller and a read-only monitoring plane
carrying map and obstacles to the operator.

**Tech stack:** ROS 2 Jazzy, Gazebo Harmonic, Nav2 1.3.12, TIA Portal V21 /
PLCSIM Advanced V7.0 (CPU 1513F-1 PN, instance `safecell3`), asyncua, PowerShell
5.1 for the PLCSIM API path.

## Global constraints

Every task's requirements implicitly include these.

- **Safety never traverses the network** (invariant 1). Safety is onboard and in
  the F-CPU; the network carries process data only.
- **Network loss is a degraded mode, not a safety event** (invariant 2).
- **The PLC is the OPC UA server, the client never inverts** (invariant 4).
- **One owner per datum** (invariant 10). No consumer recomputes what a layer
  already owns.
- **The control loop closes onboard; no velocity value crosses the OPC UA seam**
  (ADR 0014).
- **PLr targets only** — never an achieved PL, Category, SIL or PFH
  (ADR 0011 D5). The stand-in paths are standard DBs and say so wherever they
  appear.
- **Agents do not commit.** The orchestrator commits by pathspec.
- **Evidence is written as it lands**, never held for the end.
- **Every figure states its n.** A single run is an observation, not a bound.
