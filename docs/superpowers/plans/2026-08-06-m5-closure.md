# M5 closure implementation plan — safety first

> **For agentic workers:** this project's execution unit is a **brief** under
> `docs/briefs/`, dispatched to a roster agent, answered by a **report** under
> `docs/reports/` — CLAUDE.md §5, which overrides the step-level TDD format the
> writing-plans skill defaults to. Each task below is one brief.

> **RE-ORDERED 2026-08-06** on the owner's ruling. The presentation is
> **safety-PLC focused**. The safety chain is the deliverable; autonomous
> driving needs a working first prototype and nothing more.

**Goal:** A safety chain that works and is simulated as realistically as we can
make it — the encoder, the scanner and the e-stop working **perfectly**, SLS and
the stop working properly — with autonomy as a supporting prototype.

**Architecture:** Gazebo sensors → field evaluation → the stand-in writer →
`SafetyInputStandIn` → the F-program (the vehicle's onboard safety controller)
→ demands → the `Forklift/Safety/` mirrors → the bridge → the vehicle's inhibit.
The standard program forms the envelope; the F-program monitors and demands.

**Tech stack:** ROS 2 Jazzy, Gazebo Harmonic, TIA Portal V21 / PLCSIM Advanced
V7.0 (CPU 1513F-1 PN, instance `safecell3`), asyncua, PowerShell 5.1.

## Global constraints

- **Safety never traverses the network** (invariant 1); **network loss is a
  degraded mode** (invariant 2); **the PLC is the server** (invariant 4);
  **one owner per datum** (invariant 10).
- **No velocity value crosses the OPC UA seam** (ADR 0014). The F-program emits
  **demands, never speeds**.
- **PLr targets only** — never an achieved PL, Category, SIL or PFH
  (ADR 0011 D5). Every stand-in path says it is one, wherever it appears.
- **The cell e-stop stops no vehicle** (SRS B4). The vehicle e-stop stays
  deferred to M6 — owner ruling, 2026-08-06.
- **Agents do not commit.** Evidence is written as it lands. Every figure
  states its n.
